1. 字段名称不统一（最典型的 KeyError 坑）
现象：程序在处理不同专区下载的报表时，经常报 KeyError: '采购企业'。

坑点：原始数据极不规范。有的专区导出的表格叫“采购企业”，有的叫“采购部门”，甚至有的叫“下单单位”。

解决方案：我们在代码中引入了动态识别逻辑。先对列名进行 strip() 去空格处理，然后通过 if-elif 逻辑优先寻找“采购企业”，找不到再找“采购部门”，从而兼容不同来源的数据。

2. 合并单元格导致的“数据缺失”
现象：统计出的总金额远低于实际金额，或者大量订单找不到对应的企业。

坑点：Excel 导出时为了美观，经常在“一单多货”的情况下合并“订单号”、“采购企业”和“订单金额”单元格。但在 Pandas 读取时，除了第一行有值，其他行全是 NaN（空值）。

解决方案：在所有分析逻辑开始前，必须先执行 .ffill()（向下填充）。确保每一行商品明细都能正确关联到其所属的订单号、企业名称和订单状态。

3. “一单多货”的金额统计陷阱
现象：如果直接对“订单金额（元）”列求和，数值会翻倍（因为每个商品行可能都标了整笔订单的总额）；或者如果只取首行，又容易因为切片问题漏掉数据。

坑点：原始报表中的“订单金额”列逻辑不一致，有时是单行金额，有时是订单总额。

解决方案：引入了金额重算逻辑。不再依赖原始的“订单金额”列，而是强制使用 单价 * 数量 计算出每一行的真实金额，再进行 groupby 汇总，彻底解决了金额不准的问题。

4. Excel 表头不可见空格
现象：代码里明明写了 df['采购企业']，且 Excel 里也叫这个名字，但程序就是报错找不到。

坑点：Excel 表头里经常带有肉眼看不见的空格或换行符（例如 "采购企业 " 或 "\n采购企业"）。

解决方案：在读取 Excel 后的第一步，统一执行 df.columns = [str(c).strip() for c in df.columns]。这个操作虽然简单，但解决了 80% 以上的 KeyError。

5. 流程阻塞与容错性差
现象：一旦其中一个模块（如“供应商分析”）因为数据问题报错，整个自动化流程（包括后面的“可视化看板”和“话术生成”）全部崩溃，用户拿不到任何结果。

坑点：早期的 main.py 采用的是线性调用，缺乏保护。

解决方案：在 workflow.py 中使用了 try...except 循环捕获机制。将 10 个分析步骤封装成任务列表，某一步报错时，程序会跳过该步骤并打印错误提示，继续执行下一步。这保证了系统的高可用性。


6. Word 替换导致的格式丢失（样式杀手）
现象：生成的报告虽然文字对了，但原模板里的加粗、红色字体、宋体小四全变成了默认的等线体。

坑点：直接赋值 `paragraph.text = "xx"` 会抹除该段落所有的 `Run`（样式块）。Word 的样式是保存在 `Run` 里的。

解决方案：改用 **Run 级高保真替换**。代码会遍历段落中的每一个 `Run`，只修改 `run.text`。这样可以完美保留模板中预设的字体颜色、加粗和字号。


7. 绝对路径导致的分发失败（“在我电脑上能跑，他那里不行”）
现象：打包后的程序发给同事，点击“运行分析”没反应，或者报找不到模板。

坑点：代码里硬编码了 `D:\OrderDataHandle\...`，到了别人电脑上路径全变了。甚至在 GUI 里，点击“Run Analysis”不成功，必须重新选择一下文件夹。

解决方案：引入了 **路径自愈逻辑**。在 `core.config` 中统一使用 `get_base_dir()` 探测当前运行环境（源码还是 EXE）。在 GUI 初始化时，如果发现配置文件里的路径在当前环境下失效（比如找不到文件夹），程序会自动重定向到同级目录下的 `resources` 或 `template`，实现了“零配置”分发。


8. ECharts 图表提取“白版”与“ID 漂移”
现象：HTML 看板里有图，但 Word 里的图表位是空的，或者报 JS 错误 `toDataURL of undefined`。

坑点：Pyecharts 默认生成的 Div ID（如 `1b6e58...`）是随机的，每次生成 HTML 都会变，硬编码 ID 必死。此外，Headless 浏览器如果不等 Canvas 渲染完就截图，截出来就是空的。

解决方案：
- **ID 锁定**：在绘图层显式指定 `chart_id`，确保 ID 永不变更。
- **渲染循环探测**：在 Selenium 脚本中加入 JS 判定，如果 `toDataURL` 返回空，则每 0.5s 轮询一次（最多等 5s），确保渲染完成后再取图。
- **离线资源**：将 Pyecharts 资源服务器切换到国内 BootCDN 镜像，解决了外网加载慢导致的渲染超时。


9. 打包后的“灵异”报错：No module named 'selenium.webdriver...'
现象：源码运行正常，但打包成 EXE 后，一旦运行到截图环节就崩溃。

坑点：PyInstaller 的静态分析器有时会“精简”掉 Selenium 这种通过动态反射加载的子模块，导致打包后的环境里没有特定的驱动类。

解决方案：
- 在脚本头部使用 **强效显式导入**：`import selenium.webdriver.chrome.webdriver`。
- 在打包命令中加入 `--collect-all selenium`。


10. 占位符残留与括号残留
现象：图表插入后，Word 里多出了一个孤零零的 `{}`。

坑点：Word 会把 `{{CHART_MARKER}}` 自动切分成多个碎小的 `Run`。只替换文字 `CHART_MARKER` 会留下花括号。

解决方案：在识别到标记后，物理清空该段落的所有 `Run` 再插入图片。同时在匹配算法中兼容 `{{MARK}}`、`{MARK}` 和 `MARK` 三种写法，确保一次性杀干净。

11. 文件句柄失效陷阱（Metadata Exception）
现象：程序在读取“新注册供应商表”时报“元数据异常”，但 Excel 里明明有这张表。

坑点：在 Windows 下，如果在同一个 Python 函数内先用 `pd.ExcelFile` 打开了文件，中途又用 `pd.ExcelWriter` 对该物理文件执行了保存操作，会导致之前的 `xls` 对象句柄失效或无法识别更新后的文件结构。

解决方案：将所有读取操作（`xls.parse`）统一提前到函数的最开头执行，并将数据存入内存变量，确保在任何写回操作发生前，所有必需的数据已经加载完毕。


12. 区间切片“丢掉最后一天”的数据陷阱
现象：统计出的总金额或订单量总比实际少，核对发现最后一天（如3月31日）下午或晚上的订单全部没统计进去。

坑点：Pandas 的 `pd.to_datetime` 转换纯日期字符串时，默认生成的时刻是 `00:00:00`。在执行 `df['日期'] <= end_date` 的布尔过滤时，最后一天凌晨以后的数据会被判定为“超出范围”而被剔除。

解决方案：在 `data_wash.py` 和 `core_metrics.py` 的切片逻辑中，对 `end_date` 执行物理补全。通过累加 `pd.Timedelta(days=1) - pd.Timedelta(seconds=1)`，将结束时间强制锁定在当天的 **`23:59:59`**，确保分析时段能覆盖到最后一秒。


13. ECharts 图表文本截断与 Pyecharts 版本兼容性
现象：环形图文字太长显示为省略号，且尝试在代码中传 `width` 或 `overflow` 参数时直接报 `Unexpected keyword argument` 导致程序崩溃。

坑点：Pyecharts 2.x 的 Python 封装层并不完全支持 ECharts 5 所有的原生渲染参数。直接传参会由于类定义里没有该字段而报错。

解决方案：
- **视觉扩容**：大幅调宽画布（1200->1800px），减小饼图半径（70%->45%），为文字腾出位置。
- **JS注入换行**：使用 `JsCode` 编写 Javascript 格式化函数，在前端渲染时手动按字数切分换行，绕过了 Python 端的参数限制。


14. 坐标轴“悬空”与视觉对比度太低
现象：折线图和柱状图的纵轴（Y轴）在白色底色下几乎看不见，图表像悬在半空。

坑点：Pyecharts 默认不显式开启轴线，或者轴线颜色设置得极其接近背景色（浅灰色）。

解决方案：显式配置 `axisline_opts=opts.AxisLineOpts(is_show=True)`，并将颜色加深至 **深灰色（#606266）**。同时确保 X 轴 and Y 轴颜色统一，提升了看图时的“踏实感”。


15. 跨月（多月份）区间统计的“盲区”逻辑
现象：当分析区间选为 1月-3月时，提取的核心指标（如交易总额）竟然只有 1 月份的数据。

坑点：原本的汇总表逻辑是按月分割的，表格末尾只有每个月的“小计”，缺乏一个代表整个区间的“总计”行。提取逻辑默认抓取第一个匹配项，导致了严重的数据遗漏。

解决方案：在 `order_analysis.py` 中引入了“区间总计”行（基于全区间数据去重计算），并更新 `core_metrics.py` 的抓取优先级，确保在多月份汇总时能拿到真实的全区间总和。


16. 柱状图 X 轴标签重叠与视觉拥挤
现象：当月份数量较多（如 10 个以上）时，X 轴的日期标签（如“2023-01”）挤在一起，完全无法阅读。

坑点：Pyecharts 默认将所有 X 轴标签都显示出来，且没有自动旋转或截断机制。这在长图表中是典型的布局灾难。

解决方案：在 `create_bar_component` 中，通过 `xaxis_opts.axislabel_opts.rotate` 强制将标签旋转 **45 度**。这使得标签从水平变为斜向右上，利用了垂直空间，完美错开重叠，同时保持了 20px 的大字号。
